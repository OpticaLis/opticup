## 2026-05-07 — M14 Architecture Brief sealed (26 locked decisions)

**Context:** M14 = pre-scheduled appointments (exam, pickup, briefing). Replaces yoman.co.il. Domain-neutral (suitable for any appointment-driven business: optical, doctor, salon, garage, studio). Public booking flow + staff calendar + reminder integration via M12 + resource-level notifications.

**Brief structure:** 11 entities, 6 dedicated Views, 8 RPCs, 4 approved mockups (main calendar + 3 sub-screens), 26 locked decisions, deferred list documented in §6.

**Locked decisions (full list in Brief §9):**

1. M14 = Appointments only. M15 = Queue (separate module).
2. Day-1 scope = essentials; deferred = rest (10+ items).
3. Public booking page = M14 own URL (`book.opticalis.co.il/{tenant}`), not embedded in M3.
4. Booking minimum fields: name + phone + type + slot. Email optional.
5. Family-phone privacy: server doesn't list customers; asks for name; matches phone+name.
6. OTP tenant-configurable, default off. 3 wrong attempts = 24h lockout.
7. Working hours: 2-layer (`branch_hours` + `branch_hours_exceptions`).
8. Display hours ≠ booking hours (staff can manually book outside booking-window, inside display-window).
9. Reminders flow through M12 (Pattern 10 — Fact-vs-Rule).
10. Cancellation: customer side = single "manage" link. Staff side = reason + checkbox-suppress-message.
11. Reschedule = DELETE-old + CREATE-new (2 events in reports).
12. Duplicate-booking = warn but allow.
13. No-show: manual-mark + reason + 3+/12m flag on customer card.
14. Confirm-arrival button (from yoman) + .ics + Google Calendar links.
15. Appointment types simple: name + duration + max-per-day + color + assigned-resource. No age limits day-1.
16. Resource selection in booking flow tenant-configurable. Resource-label string ("optometrist"/"doctor"/etc.).
17. Branch selection in booking (if multi-branch).
18. Calendar interactions: click-empty=quick-create, right-click=block, drag=reschedule, double-click=details.
19. Default view: Day. Week+Month available.
20. Dashboard = action-oriented (not metric-dashboard like yoman).
21. Dual-color appointments: type-fill + status-outline (always both).
22. Statuses = system-rows (7 fixed) + tenant-rows (free). Pattern 13.
23. Lunch break = light-gray-shaded, bookable but discouraged.
24. Resource-level reminders (yoman insight): each resource has phone+email+toggle.
25. "Awaiting staff approval" status → tenant-configurable toggle (default off).
26. 4 mockups approved.

**Key cross-module patterns surfaced:**
- **Pattern 10 (Fact-vs-Rule) reinforced:** M14 emits facts ("תור #X נקבע / בוטל / מחר ב-10:00 / נקבע למשאב Y"); M12 owns the rules ("שלח אישור / שלח תזכורת 24h / שלח הודעה למשאב כשנקבע לו תור").
- **Resource-level notification pattern (NEW from M14):** Each `resources` row has `phone` + `email` + `send_notifications boolean` + `sms_enabled` + `email_enabled`. Resources are not just data containers — they are notification destinations. Generalizes to any future "assigned-to" entity.

## 2026-05-14 — Module Close Ceremony — M14 (backlog batch close)

**Context:** Brief sealed 2026-05-07 (26 decisions, 11 entities, 6 Views, 8 RPCs, 4 mockups). Ceremony ran 7 days later as part of `OVERNIGHT_BUNDLE_2026_05_14` Tier D backlog batch.

**Reviewed:** Brief §1-§9 end-to-end + 3 mockup files (`M14_APPOINTMENTS_MOCKUP.html` + `M14_APPOINTMENTS_SCREENS.html` + Brief content).

**Patterns reinforced by this batch close:**

1. **P40 — Configurable-per-tenant DEFAULT for UI layout / type / category / option lists.** M14 has FOUR independent config tables: `appointment_types` + `appointment_statuses` (system + tenant rows) + `cancellation_reasons` + `branch_hours_exceptions`. Combined with M5 (customer-list density/columns) and M11 (categories/visibility/columns), this becomes the 3-strike trigger for **P40** in SKILL.md.

2. **P41 — Manual-now-with-auto-twin-hook.** M14's `send_notification` checkbox on staff cancellation is the manual gate; M12's future rule engine reads cancellation events and decides automatic firing. M14 itself emits the fact (cancellation event with `send_notification` flag); M12 future owns the rule. Combined with M7 (5 manual forms) + M12 (manual templates + AI slot reserved) + M15 (manual queue-add), this becomes the 4-strike trigger for **P41** in SKILL.md.

3. **Resource-level notifications pattern (new in M14)** — Daniel's yoman insight: when a customer books an appointment, the **resource** (optometrist/doctor) also receives a notification. Resources are notification destinations. Schema: `resources.phone` + `resources.email` + `resources.send_notifications` toggle + `resources.sms_enabled` + `resources.email_enabled`. Captured here; NOT promoted to a Pn yet (single-instance) — generalizes to any future "assigned-to" entity (M9 stations/staff, M7 lab technicians, M8 cashiers). Re-evaluate at M9 build SPEC.

4. **Dual-axis visual encoding (type-fill + status-outline)** — M14 appointment block visual = appointment_type color FILL + appointment_status color OUTLINE. Two orthogonal classifications shown without overload. Captured here; NOT promoted yet — generalizes to any entity with two orthogonal classifications (e.g., M7 sub_order type-fill + state-outline, M9 lab-tag stage-fill + priority-outline). Re-evaluate at M7 V7 implementation SPEC.

5. **Display hours ≠ booking hours (separation of public-facing window from internal-operational window)** — yoman doesn't have this; OpticPlus didn't have this; Daniel's directive 2026-05-07. Generalizes to any "we're open 8am-8pm but only book 9am-7pm" business. Captured here; NOT promoted (single-instance).
