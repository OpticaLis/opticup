## 2026-05-24 — M6 editor input-behavior rules (Daniel-approved, post-launch polish)

Daniel tested the live M6 editor on demo and requested professional input-behavior. All approved:

**Sign defaults + steps:**
- SPH / CYL: default MINUS, step 0.25, always 2 decimals. Typing "5"+Enter → "-5.00". Plus only if
  user types "+5" explicitly.
- READ/INT/BIF/MUL-add (per-eye ADD block): default PLUS, step 0.25, 2 decimals. "1.5" → "+1.50".
- **Momentary visual highlight when a sign is auto-applied** (field flashes / sign colors briefly) so
  a fast typist who meant +5 but got -5.00 SEES it. (Daniel approved — prevents silent clinical error
  while keeping the speed of default-minus.)

**Unit / symbol suffixes (applied on blur or Enter):**
- AXIS: degrees °, integer 0–180 ("175" → "175°"). K-axis same.
- PRISM: value + prism diopter sign △, step 0.25 ("4" → "4.00△"). BASE stays a picker (UP/DN/IN/OUT).
- PD / BC / DIA / Pupil / axial-length: millimetres "mm" ("32" → "32mm", "8.4" → "8.40mm").
- VA (VAcc/VAsc/PH): 6/x format preserved, no suffix.
- Kerato (K1/K2/Kavg): 2 decimals per standard; K-axis = degrees.

**Edit-mode behavior:**
- Symbols/defaults update AFTER Enter OR field-blur (move to another field).
- On entering a field to edit, the displayed sign/default disappears → clean write mode; re-applied on
  commit.

**Lesson (P-AR — input-behavior is domain UX, not cosmetics):** for professional data-entry screens,
sign/unit normalization + step granularity is a real requirement that defines whether pros adopt the
tool. Treat it as first-class, not polish. Daniel: "תחשוב איך עוד אפשר לשפר את זה בשביל חוויה מושלמת
לאופטומטריסטים" — so the Brief also proposes additional professional-UX improvements for his review.
