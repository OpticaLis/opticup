## 2026-05-06 — M6 state-machines: explicit, not boolean. Pattern lifted to cross-module level.


**Situation:** OpticPlus uses `bdka` boolean flag for draft/commit. Decision: keep boolean or use explicit state-machine.
**My recommendation:** Explicit state-machine. exams: scheduled/in_progress/completed/cancelled. prescriptions: draft/committed/superseded/expired. Plus status_changed_at + status_changed_by on each entity for traceability.
**Daniel's response:** "תחליט אתה. העיקר שזה יהיה בנוי נכון וגמיש מספיק לשינויים עתידיים."
**Reason for delegation:** Daniel trusts technical-architectural decisions when correctness + future-flexibility are the deciding criteria.
**Lesson 1:** When the decision criterion is "correctness + flexibility", that is mine to make. Don't kick it back. P2 hard rule applies.
**Lesson 2:** "Flexible for the future" with Postgres enums = use enum (allows ADD VALUE without migration), plus side-table audit fields (status_changed_at/by). Codifying as a sub-pattern of P17.
**Lesson 3:** This state-machine pattern lifts to ALL Architecture Briefs — M7 orders (draft/confirmed/in_lab/ready/delivered/cancelled), M8 payments (pending/posted/reversed) all need explicit states, not booleans. Adding to M6 brief AND noting it's a cross-module pattern.


## 2026-05-07 — M7 forms consistency pass + 5 fixes


**Situation:** Reviewed all 6 M7 artifacts (main mockup + 5 forms + catalog). Found 6 inconsistencies/gaps. Daniel approved 5 fixes:

1. **Terminology consistency:** 4 sub-order types only (frame/lenses/contacts/accessories). Phrases like "frame+lenses" are *content* (display label in the rail), not *type*. Daniel: agreed. Updated all forms + catalog now has explicit "כללי-יסוד" section locking this.
2. **Reservation default expiry:** 7 days, tenant-configurable. Daniel: agreed. Documented in catalog "כללי-יסוד".
3. **Min-deposit (50%) for converting reservation/quote → order:** Daniel: keep manual for now. "Convert to Order" stays a manual button even when min-deposit threshold is met. Documented as "כרגע ידני" in catalog.
4. **"Thanks" message logic:** Sent only when BOTH conditions: order state=`active` AND total payment ≥ ₪1. Reservation+partial-deposit alone does NOT trigger. Daniel: explicit — "בדרך כלל ב-RESERVATION לא משלמים מקדמה. גם אם כן - לא צריך לשלוח הודעה. רק כשההזמנה ACTIVE ויש תשלום כלשהו." Locked in main mockup tooltip + catalog "כללי-יסוד".
5. **Lab status field is dual-tracked:** Printed form shows manual checkbox (for the lab-basket workflow), computer is source-of-truth (M9 barcode scan auto-updates). Daniel agreed. Documented in catalog Order Inspection row + global "כללי-יסוד".
6. **Tear-off customer receipt — REMOVED.** I had added it to Order Inspection. Daniel rejected it sharply — receipt/invoice is a cashier responsibility, not a form. Future: API integration with external POS like LINET handles all customer-facing financial documents. M7 forms are 100% internal-only. Removed tear-off from all 5 Order Inspection variants + updated catalog.

**Lesson 1:** I keep over-designing customer-facing artifacts that aren't M7's job. The M7/cashier boundary is firm: M7 does internal workflow paper, cashier (POS API later) does customer-facing paper. Future modules: when a deliverable is "customer-facing financial" (receipt, invoice, statement, refund slip), check if it belongs to M7 at all. Probably not — cashier territory.
**Lesson 2:** "Reservation with partial payment" is a real edge case Daniel explicitly addressed: payment ≠ commitment-to-buy. The trigger for "thanks" is the *commitment state* (active), not the *money flow* (payment ≥ 1). State-machine drives messaging, not the cash-flow event. Generalizable: when designing automated outreach, always trigger on intentional state transitions, never on side-effects of those transitions.
**Lesson 3:** Forms catalog should have a top-level "shared rules" section before per-form details. Cross-cutting rules (terminology, message logic, status sources, configurability defaults) repeat across forms. A single source for these prevents drift. Established now in M7 catalog — should propagate to future module catalogs.
