החלטות-עיצוב במסך-לקוח

  • 5 לשוניות: פרטים · תפקודי ראייה · בדיקות ראייה · הזמנות · מסמכים. (Update הוחלף ב-Docs, Glasses+Contacts אוחדו לתצוגת-תקציר על M6.)
  • תפקודי ראייה — לשונית-עצמאית עם רשימת-בדיקות-מקיפה (24 בדיקות-תפקוד: ortho/exo, AC/A, Bo/Bi בכל מרחק, NRA, PRA, Push-Up, Stereopsis, MEM וכו'). בורר-תאריכים — לקוח יכול להיות עם מספר בדיקות לאורך השנים.
  • בדיקות ראייה = תצוגת-תקציר על M6 בלבד. רשימת-בדיקות ראייה בשורות (תאריך · סוג · סטטוס · אופטומטריסט · תקציר R/L · תוקף · הערות · פעולה). לחיצה על "פתח ב-M6" עוברת למסך-מרשם המלא של מודול-M6 — בדומה לאיך שלשונית-הזמנות פותחת את מסך-M7. מודול-בדיקות ראייה נפרד מאפשר scaling לעוד ענפים בעתיד (שיניים, ווטרינריה).
  • "ערוך" כפתור-בכותרת, לא לשונית. לחיצה מפעילה מצב-עריכה גלובלי בכל הלשוניות.
  • שמירה אוטומטית בכל המסך — כמו ב-M7. אין כפתור "שמור".
  • Queue ב-Details — בלוק טורקיז מציג את מצב-התור הנוכחי (תור #2 · ממתין 12 דקות) או כפתור "+ הוסף לתור-בדיקה". מנוהל ב-M14, חשוף בכרטיס-הלקוח.
  • Medical Q. + Diagnostics אוחדו לבלוק "הערות-רפואיות" עם 2 sub-tabs בתוך Details.
  • Birthday auto-message מסומן כ"עתיד — מודול-תקשורת/אוטומציות". כרגע ידני.
  • Orders = מסך-M7 מלא — בלחיצה על הלשונית עוברים ל-layout-מלא של M7. הסקיצה כאן מציגה רק תקציר + כפתור-מעבר.
  • Docs עם קטגוריות — מרשם-רופא / בדיקה-חיצונית / קופ"ח / אחר. קונפיגורבילי פר-tenant.
  • כותרת-עליונה אחידה בכל הלשוניות — שם + גיל + טלפון + פעולות-מהירות.
דרישות-מערכת (חוצה-מודולים):
  • M5 (Customers): Birthday auto-message — שדה birthday_message_consent + טריגר עתידי. Notes (business + medical) — טבלה customer_notes עם note_type enum.
  • M6 (Prescriptions — מודול-עצמאי): בעלות מלאה על eye_exams (תפקודי ראייה) + prescriptions (משקפיים + עדשות-מגע, שתי טבלאות נפרדות). View v_customer_prescriptions_summary(customer_id) משרתת את לשונית-3 בכרטיס-הלקוח. View v_customer_vision_function_history משרתת את לשונית-2.
  • M14 (Appointments + Queue): בעלות על תור-החנות. View v_customer_queue_position(customer_id) + RPCs: add_to_queue, remove_from_queue, promote_in_queue. כרטיס-הלקוח קורא דרך View, לא נוגע בטבלה ישירות.
  • Docs (חלק מ-M5): Supabase Storage Bucket פר-tenant. Path בתבנית tenant_id/customer_id/... — ללא עברית בנתיב. קטגוריות = טבלה קונפיגורבילית פר-tenant (Iron Rule 19) עם flags (e.g. is_medical).
  • Edit-mode: הרשאות פר-תפקיד (Iron Rule תהיה במקום). רק מנהל יכול לערוך פרטי-תקשורת או לשנות-קופ"ח.
  • Scaling-עתידי לענפים: כשנכנס ענף חדש (שיניים/ווטרינריה) — M5 (Customers) נשאר זהה, M6 מוחלף במודול-בדיקות ראייה-של-אותו-ענף. הלשונית-3 בכרטיס-הלקוח טוענת view שמתאים לענף הפעיל. כל מודול-ענף מספק את אותם 3 contracts: רשימת-בדיקות ראייה-לקוח, מסך-מרשם-מלא, רשימת-תפקודים (אופציונלי).
